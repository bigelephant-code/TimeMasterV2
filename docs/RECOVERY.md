因此，后续功能没有 Git 提交并不是 Git 丢失了提交，而是这些修改从未发生在受版本控制的工作树中。最终保留下来的权威产物是 Windows 安装包。

## 恢复方法

1. 将 NSIS/Electron 安装包按 7z 容器只读提取。
2. 提取 `resources/app.asar`。
3. 使用 ASAR 工具展开应用内容。
4. 对展开后的主进程、preload、HTML、CSS 和 JavaScript 做完整性及敏感信息检查。
5. 将可读运行源码保存到 `runtime/`，并把 `package.json` 的入口指向 `runtime/main/index.js`。
6. 重新打包并比较关键文件、应用身份和功能入口。

原安装包没有携带 source map 或原始 `.vue` 单文件组件，所以不能机械地百分之百还原组件文件边界。恢复出的 JavaScript 和 CSS 未压缩混淆，变量名、注释、数据结构和功能逻辑均可直接审查。

## 当前目录含义

- `runtime/`：0.1.3 安装包中的当前运行源码，是重新打包和功能核对的依据。
- `src/`：0.1.0 LiteCal 的历史模块化源码，用于逐步恢复清晰模块边界。

## 后续维护原则

- 禁止只保留安装包而不提交源码。
- 每个可发布版本必须有 Git 标签、变更记录和可重复构建命令。
- 逐步将 `runtime/main/index.js` 拆回存储、提醒、窗口、IPC 和导出模块。
- 逐步将渲染层恢复为 Vue 单文件组件，并为数据迁移和台账导出补充测试。

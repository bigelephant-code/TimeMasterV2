# 轻日历 LiteCal

一个只做日历本职工作的 Windows 桌面日历。功能对标小智桌面日历的核心部分，
砍掉了 AI、会员、皮肤商城、账号体系、第三方/订阅日历、埋点上报、任务栏 hook、壁纸。

**这是独立重写的实现**：没有反编译任何二进制、没有使用对方的图片/皮肤资源、
不连接对方的任何服务端接口。农历、节气、法定节假日全部本地离线计算。

## 功能

| 模块 | 说明 |
|---|---|
| 日历 | 月 / 周 / 日三种视图，公历 + 农历 + 24 节气 + 中国法定节假日与调休（休/班角标） |
| 待办清单 | 多清单、日期时间、优先级、重复（每天/周/月/年）、按逾期·今天·将来·无日期分组 |
| 四象限 | 艾森豪威尔矩阵，拖拽在象限间移动；与待办共用一份数据 |
| 到点提醒 | 系统托盘常驻 + Windows 原生通知，可提前 5/15/30/60 分钟或 1 天 |
| 桌面小组件 | **当日四象限面板**：日期 + 农历 + 时钟 + 年度刻度 + 长期目标 + 今天的四个象限 |
| 事件计时 | 每条待办可「启动 / 结束」，完成后按分钟结算耗时 |
| 长期目标 | 设总值 + 单位，进度按增量累加，百分比进度条展示 |

### 小组件怎么用

小组件从上到下三块：**日期头 → 长期目标 → 今日四象限**。

日期头分两行：上面是大号日期 + 年月 / 星期 / 农历干支 + 时钟 + 今日完成数；
下面一条统计带，三格并列显示 **本年第几周**、**年内还剩多少天**、**今日待办件数**。
年内剩余 ≤ 30 天时那个数字转琥珀色。

**待办**

- **右键任意象限** → 新增表单，象限已预填，日期默认今天，时间可留空。
  填了未来日期就存到那一天，不出现在今天的面板里（表单会提示存到哪天了）。
- **双击卡片** → 改标题、日期、时间、象限，也能删。
- 每条待办两个按钮：**▶ 启动计时** 和 **✓ 完成**。
- 只显示今天的待办。从主窗口快速添加、还没归象限的，暂时收在「重要且紧急」，
  顶部会有一条横幅说明，避免它们凭空消失。
- 新增统一走右键，顶栏没有 + 按钮。

**长期目标**

这一块没有标题文字，直接就是目标行（名称 + 当前/总值 + 百分比 + 进度条）。

- **右键目标区** → 新建，填名称、总值、单位（本 / 篇 / 公里…）、当前值
- **点目标那一行** → 就地弹出输入框，填**增量**回车即可（比如读完 3 本就填 3，会累加）
- **右键某个目标** → 改名称 / 总值 / 单位 / 当前值，或删除
- 增量可以填负数用来修正记错的量；每次新增都会在 `history` 里留一条流水（最多存 100 条）

**窗口**：拖边缘改大小，尺寸和位置都会记住。

### 卡片的三种颜色

| 状态 | 颜色 | 触发条件 |
|---|---|---|
| 计时中 | 绿 | 点了「启动」，同时跳 mm:ss 秒表 |
| 临期 / 逾期 | 玫红 | 设了时间，且距离截止 ≤ 30 分钟（含已逾期） |
| 已完成 | 置灰划线 | 勾选完成，后面跟「用时 N 分钟」 |

计时中又临期时，**底色保留绿、外面套一圈玫红描边**——底色是点「启动」换来的即时反馈，
被顶掉会让人以为没点上，所以两个信号分开表达。

计时可以中途停了再启动，耗时累加。计时中直接点「完成」等同于先按停止，
那一段时间不会白跑。重复待办滚到下一次时耗时清零，重新计。

## 技术栈

- **Electron 43** + **Vue 3** + **Vite 7**（electron-vite 打包）
- **lunar-javascript** 算农历/节气/节假日，完全离线
- 数据存本地 JSON（`%APPDATA%\litecal\`），原子写入

## 运行

```bash
npm install
npm run dev
```

首次装依赖若卡在 Electron 二进制下载（国内网络），用镜像：

```bash
set ELECTRON_MIRROR=https://registry.npmmirror.com/-/binary/electron/ && npm install
```

npm 11 默认拦截安装脚本，如果 `node_modules/electron/dist/electron.exe` 不存在：

```bash
npm approve-scripts electron esbuild && node node_modules/electron/install.js
```

## 打包

```bash
npm run dist
```

产物在 `release/`，NSIS 安装包，可选安装路径。

## 实测开销与取舍

本机实测（Windows 11，主窗口 + 小组件都开着）：

| | 进程数 | 工作集 | 私有提交 | 安装包 |
|---|---|---|---|---|
| LiteCal | 5 | 483 MB | 247 MB | 88.8 MB |
| 小智桌面日历（同机对照） | 17 | ~870 MB | — | — |

**说明一下这个数字**：小智那 870 MB 里有 281 MB 是 AI 助手，这块我们整个砍掉了。
去掉 AI 只比日历+小组件的话，小智约 590 MB，LiteCal 483 MB —— 只省两成左右，
不是数量级的差距。原因是 Electron 43 用的 Chromium 比它的 CEF 89 新了 60 多个版本，
单进程内存本身就更重，抵消掉了进程数从 17 降到 5 的收益。

真正确定性的收益在别处：

- 进程从 17 个降到 5 个，没有常驻后台服务、没有计划任务、没有任务栏 hook
- 零联网：不上报任何埋点，不请求任何服务端
- Chromium 从 89（2021 年）换到 43 版 Electron 自带的新内核，安全补丁跟得上
- 数据是明文 JSON，随时可读可备份可迁移

**如果内存是首要目标**，换 Tauri 2 外壳能落到 60–100 MB、安装包 8–15 MB
（复用系统已装的 WebView2 150）。前端代码基本可以原样搬过去，
代价是要先装 Rust 工具链和 Visual Studio C++ 生成工具（约 4–6 GB）。

## 数据

| 文件 | 内容 |
|---|---|
| `%APPDATA%\litecal\data.json` | 清单、待办、长期目标 |
| `%APPDATA%\litecal\settings.json` | 界面设置、窗口位置、小组件配置 |

开发版和打包版共用同一个目录（`app.getName()` 取的是 package.json 的 `name`），
所以调试时造的数据装完之后还在。

明文 JSON，随时可以自己备份、编辑、写脚本导入导出。
损坏时会自动改名成 `.broken-<时间戳>` 留档，不会静默覆盖。

## 键盘快捷键

| 键 | 作用 |
|---|---|
| `T` | 回到今天 |
| `N` | 新建待办 |
| `←` `→` | 上一页 / 下一页 |
| `1` `2` `3` | 日历 / 待办 / 四象限 |
| `Esc` | 关闭弹窗 |

## 结构

```
src/
├── main/          Electron 主进程
│   ├── index.js       生命周期、托盘、单实例锁
│   ├── windows.js     主窗口 + 小组件窗口
│   ├── store.js       JSON 持久化 + 数据仓库
│   ├── reminder.js    提醒轮询调度
│   ├── ipc.js         IPC 接口
│   └── icon.js        运行时生成图标（无二进制资源）
├── preload/       contextBridge 白名单
└── renderer/
    ├── index.html     主窗口
    ├── widget.html    小组件窗口
    └── src/
        ├── App.vue / Widget.vue
        ├── store.js       渲染层响应式状态
        ├── lib/date.js    日期计算
        ├── lib/lunar.js   农历封装
        └── components/
```

数据层出口全收敛在 `src/main/store.js` 的 `repo` 对象，将来要换成 SQLite 只需改这一个文件。
